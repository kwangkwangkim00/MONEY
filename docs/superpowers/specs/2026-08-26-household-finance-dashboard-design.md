# 우리집 재무관리 대시보드 설계

## 목적

부부가 함께 보는 가계 재무 대시보드. 카드사 청구내역과 마이너스통장 이체내역(학원비 등)을
거래 단위로 기록하고, 월별로 얼마가 나갔는지 한눈에 확인한다.

## 배경 / 제약

- 카드 문자(SMS) 파싱은 형식이 일관되지 않아 배제.
- 은행/카드사 공식 API 연동은 등록 절차가 복잡해 배제.
- 거래 건수가 많을 것으로 예상되어(카드 명세서 전체 항목 등) 한 건씩 타이핑은 비현실적 →
  카드사 웹사이트에서 받은 엑셀/CSV를 복사해 그대로 붙여넣는 방식으로 입력.
- 재무 데이터지만 접근 보호(로그인 등)는 요구하지 않음 — URL을 아는 사람만 접근한다고 가정.
- 카테고리 분류(식비/교육비 등)는 이번 범위에서 제외. 필요해지면 추후 추가.

## 범위

**포함**
- 출처(카드/계좌) 등록
- 거래내역 붙여넣기 입력 (컬럼 매핑 + 중복 방지)
- 월별 대시보드 (출처별 목록, 합계, 월별 추이)

**제외 (이번 범위 아님)**
- 로그인/인증
- 카테고리 분류 및 카테고리별 분석
- 은행/카드사 API 자동 연동
- 예산 설정, 알림

## 아키텍처

단일 Node.js + Express 서버. 프론트엔드 프레임워크 없이 서버가 EJS 템플릿으로 HTML을 직접
렌더링한다. 빌드 단계 없음 — 차트는 Chart.js를 CDN 스크립트 태그로 로드.

데이터는 SQLite 파일(`better-sqlite3`) 하나로 저장. 배포 시 파일이 유지되도록 영구 디스크가
있는 호스팅(Render 등)을 사용한다.

```
클라이언트(브라우저, 부부 각자 기기)
        │  HTTP
        ▼
Express 서버 ── EJS 렌더링
        │
        ▼
SQLite 파일 (better-sqlite3)
```

의존성: `express`, `ejs`, `better-sqlite3`. 그 외 프레임워크·ORM·인증 라이브러리 없음.

## 데이터 모델

```sql
CREATE TABLE sources (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,              -- "국민카드", "마이너스통장"
  type TEXT NOT NULL,               -- 'card' | 'account'
  column_mapping TEXT               -- JSON: 마지막에 지정한 컬럼 순서 기억 (예: ["date","description","amount"])
);

CREATE TABLE transactions (
  id INTEGER PRIMARY KEY,
  source_id INTEGER NOT NULL REFERENCES sources(id),
  date TEXT NOT NULL,               -- 'YYYY-MM-DD'
  description TEXT,
  amount INTEGER NOT NULL,          -- 원 단위 정수
  raw_hash TEXT NOT NULL UNIQUE     -- sha1(source_id + date + description + amount), 중복 붙여넣기 방지
);
```

`column_mapping`을 `sources`에 저장해두면, 같은 카드사를 다음 달에 또 붙여넣을 때 컬럼
지정을 반복하지 않아도 된다.

## 화면 및 흐름

### 1. 출처 관리 (`/sources`)
출처 추가/이름 변경. 목록이 짧으므로(카드 3~4개 + 계좌) 별도 페이지 없이 붙여넣기 화면 상단에
간단한 드롭다운 + "새 출처 추가" 인라인 폼으로 처리.

### 2. 거래내역 붙여넣기 (`/import`)
1. 출처 선택 (또는 새로 추가)
2. 엑셀/CSV에서 복사한 텍스트를 textarea에 붙여넣기
3. 서버로 전송 → 구분자(탭/콤마) 자동 감지 후 행/열로 파싱, 미리보기 표 렌더링
4. 각 열 헤더 아래 드롭다운(날짜/내용/금액/무시)으로 매핑 지정
   - 해당 출처에 저장된 `column_mapping`이 있으면 기본값으로 미리 채워둠
5. "저장" 클릭 → `raw_hash` 계산 후 이미 존재하는 행은 건너뛰고 나머지만 insert,
   결과 화면에 "N건 저장, M건 중복 제외" 표시

날짜/금액 파싱 실패 행은 저장하지 않고 미리보기에 에러 표시, 사용자가 매핑을 고쳐서 재시도.

### 3. 월간 대시보드 (`/`, `/?month=YYYY-MM`)
- 월 선택 (기본: 이번 달)
- 출처별 거래 목록 + 출처별 합계, 전체 합계
- 최근 6개월 월별 총액 막대그래프 (Chart.js)

## 에러 처리

- 붙여넣기 파싱: 열 개수가 안 맞거나 금액/날짜를 숫자·날짜로 못 읽는 행은 저장하지 않고
  미리보기에서 빨간색으로 표시.
- 그 외 인증 없는 개인용 앱이므로 과도한 입력 검증은 하지 않음 (신뢰된 2인 사용자 가정).

## 테스트 전략

로직이 있는 두 부분만 최소 assert 테스트로 커버 (ponytail: 로직 있는 곳엔 최소 확인 하나):
- 붙여넣기 파서 (구분자 감지, 컬럼 매핑 적용, raw_hash 중복 판정)
- 월별 합계 집계 함수

프레임워크 없이 Node 내장 `assert` + 간단한 `test_*.js` 파일로 충분.

## 배포

Render (또는 Railway) 무료 티어, 영구 디스크 마운트로 SQLite 파일 경로 유지. 배포 계정 생성과
연결은 사용자가 직접 진행.

## 향후 고려사항 (지금 범위 아님)

- 카테고리 분류 및 카테고리별 분석
- 로그인/접근 제한
- 은행/카드사 API 자동 연동
